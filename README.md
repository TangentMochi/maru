# Maru

HTTP リクエストを送る、デスクトップ向けの API クライアントです。

よく使うリクエストをあらかじめ登録しておき、画面上のキーを押して項目を埋め、「発信」で送ります。応答は HTTP ステータスに応じて `YES` / `NO` / `再考` で表示します。

[Tauri 2](https://tauri.app/) 製です。フロントエンドはビルド工程のない素の HTML / CSS / JavaScript で、見た目には [98.css](https://github.com/jdan/98.css) を使っています。

## できること

- **リクエストの登録**: 名称、メソッド、URL と、入力項目を登録します。項目ごとに、値を入れる場所（パス、クエリ、ヘッダー、ボディ）を選べます。
- **キーによる入力**: 項目に選択肢を登録すると、選択肢が画面右側のキーとして並びます。数字入力用のテンキーもあります。
- **応答の判定**: 応答を `YES` / `NO` / `再考` の3種類で示し、ステータスコードと本文を表示します。
- **4つのタブ**: F1〜F4 のタブが、それぞれ別のリクエスト、入力値、応答履歴を持ちます。
- **応答履歴**: タブごとに直近50件の応答を保持し、前後に移動して見返せます。
- **セッション**: セッションの開始から終了まで、全タブで Cookie を引き継ぎます。

## 必要なもの

- [Rust](https://www.rust-lang.org/tools/install) 1.85 以降
- [Tauri の前提条件](https://tauri.app/start/prerequisites/)（OS ごとのシステムライブラリ）
- Node.js 20 以降（フロントエンドのテストを実行する場合のみ）

## 起動

```sh
cd src-tauri
cargo run
```

配布用のバンドルを作るには Tauri CLI を使います。

```sh
cargo install tauri-cli --version "^2"
cargo tauri build
```

## 使い方

初回起動時は、サンプルのリクエスト「入場券」（`https://httpbin.org/anything/{station}` への POST）が1件登録されています。

### リクエストを送る

1. 「ｻｲﾄﾞﾒﾆｭｰ」を押し、右側のキーから送りたいリクエストを選びます。
2. 項目を埋めます。「フルキー」タブには項目の選択肢が、「数字入力」タブにはテンキーが並びます。キーボードから直接入力することもできます。
3. 「発信」を押すか、入力欄で Enter キーを押します。
4. 応答が右側に表示されます。応答を待つ間は「中止」で取り消せます。応答が30秒以内に届かない場合は時間切れになります。

応答の判定は次のとおりです。

| 判定 | 条件 |
| --- | --- |
| `YES` | ステータスが 200 番台 |
| `再考` | ステータスが 400 番台 |
| `NO` | 上記以外のステータス、または応答なし（接続不可、時間切れ、中止） |

### リクエストを登録する

画面上部の「登録」を押すと、登録画面が開きます。編集した内容は、「登録」を押すまで保存されません。

各項目には次の内容を設定します。

| 設定 | 内容 |
| --- | --- |
| 表示名 | 画面に表示する名前 |
| 送信名 | パラメーター名、ヘッダー名、または JSON のキー |
| 場所 | 値を入れる場所。パス、クエリ、ヘッダー、ボディのいずれか |
| 種類 | 文字または数値。数値のボディ項目は JSON の数値として送ります |
| 選択肢 | キーとして並べる候補。`大人1=1, 大人2=2` のように「表示=値」をカンマで区切ります |
| 初期値 | リクエストを選んだときに最初から入っている値 |
| 必須 | 空欄のままでは発信できないようにします |

場所ごとの扱いは次のとおりです。

- **パス**: URL 内の `{送信名}` を値で置き換えます。例: `https://api.example.com/users/{id}`
- **クエリ**: URL のクエリ文字列に追加します。
- **ヘッダー**: リクエストヘッダーとして送ります。
- **ボディ**: ボディ項目をまとめて1つの JSON オブジェクトとして送ります。`Content-Type` ヘッダーを登録していない場合は、`application/json` を付けます。

空欄の任意項目は送りません。

### 画面上部のキー

| キー | 動作 |
| --- | --- |
| 登録 | リクエストの登録画面を開きます |
| 開始 | セッションを開始します。中断中の場合は再開します |
| 中断 | セッションを中断します。Cookie は保持しますが、送信も更新もしません |
| 終了 | セッションを終了し、Cookie を破棄します |
| 応答 | 応答の表示を切り替えます |
| 消去 | 表示中のタブの応答履歴を消去します |
| 履歴前 / 履歴後 | 前後の応答を表示します |
| F1〜F4 | タブを切り替えます。キーボードの F1〜F4 キーでも切り替えられます |

ラベルのないキーと「一括開始」「一括終了」は、現在は機能しません。

### データの保存先

登録したリクエストは、アプリのデータディレクトリにある `requests.json` に保存します。

| OS | 場所 |
| --- | --- |
| macOS | `~/Library/Application Support/com.moromen.maru/` |
| Windows | `%APPDATA%\com.moromen.maru\` |
| Linux | `~/.local/share/com.moromen.maru/` |

応答履歴と Cookie は保存しません。アプリを終了すると消えます。

## 開発

```sh
# フロントエンドのテスト
node --test tests/*.test.js

# バックエンドのテスト
cd src-tauri && cargo test
```

| パス | 内容 |
| --- | --- |
| `src/` | フロントエンド。`index.html` をそのまま読み込みます |
| `src/js/request.js` | 登録内容と入力値から HTTP リクエストを組み立てます |
| `src/js/verdict.js` | ステータスから判定を決めます |
| `src/js/store.js` | タブ、セッション、登録内容の状態を持ちます |
| `src/vendor/` | 98.css とそのフォント |
| `src-tauri/src/lib.rs` | HTTP の送信、セッション、登録内容の保存 |
| `tests/` | フロントエンドのテスト |
